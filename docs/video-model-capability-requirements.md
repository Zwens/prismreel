# 视频生成模型能力需求说明

> 需求方：PrismReel（AI 原生短漫剧 & 视频创作平台）
> 用途：填报平台方视频生成模型能力收集表
> 日期：2026-07-29

---

## 一、业务背景（一句话）

PrismReel 把一段创意文本自动拆成分镜脚本，逐镜头生成美术资产与视频片段，再配音、按 BGM 节拍裁切、拼接导出成片。**视频模型处在"分镜 → 片段"这一步，是整条流水线的产能瓶颈和质量上限**，单个项目一次成片通常需要 30–80 个镜头片段，且带批量抽卡（同一镜头生成 2–4 版择优）。

因此我们对模型的诉求不是"能生成一段好看的视频"，而是：**同一批参数下，能稳定产出几十个互相衔接、角色不变形、时长精确、可直接进剪辑时间线的片段**。

---

## 二、需求功能总表

| # | 能力 | 优先级 | 在产品中的使用环节 | 调用量级（单项目） |
|---|------|--------|--------------------|--------------------|
| 1 | 文生视频 T2V | P1 | Playground 快速试拍；Studio 空镜/转场/环境镜头 | 5–15 次 |
| 2 | 图生视频 I2V | **P0** | Studio 分镜主链路，用已定稿的分镜定调图驱动 | 60–200 次（含抽卡） |
| 3 | 一致性模型（多参考图生视频 R2V） | **P0** | 同一角色跨镜头出场；角色+场景+道具三类参考图同时注入 | 40–150 次 |
| 4 | 动漫模型 | **P0** | 全片美术风格底座（国漫 / 日漫 / 韩漫条漫等） | 覆盖上述全部调用 |
| 5 | 4 秒档时长 | P0 | 对白单句、反应镜头、切换节奏快的段落 | 约占片段总数 60% |
| 6 | 8 秒档时长 | P0 | 运镜镜头、情绪铺陈、开场/收尾镜头 | 约占片段总数 40% |

说明：第 5、6 项不是独立模型，是**横切在 1–4 项之上的时长档位要求**——上述每一种生成模式都需要同时支持 4s 与 8s 两档输出。

---

## 三、逐项具体需求与使用方式

### 1. 文生视频（T2V）

**使用方式**：用户在 Playground 输入一段中文镜头描述直接出片；Studio 中用于没有美术资产的空镜（天空、街景、雨滴、时钟特写等）和转场镜头。

**具体要求**：
- 中文长文本理解：单条 prompt 常在 80–200 字，同时包含**景别 + 运镜 + 主体动作 + 情绪 + 光线氛围**（例："中景转推镜，少年站在天台边缘，风吹动校服衣角，逆光，黄昏，镜头缓慢推近至面部特写"）。需要模型能分别响应这几类指令，而不是只抓住画面主体。
- 支持负向提示词（negative prompt），用于压制常见劣化（多手指、面部畸变、字幕水印）。
- 支持 seed 固定，同 seed + 同 prompt 结果可复现——这是我们做参数对比和问题复现的前提。
- 支持 prompt 自动扩写开关（可关闭），扩写会改变画面构图，成片阶段必须能关掉。

---

### 2. 图生视频（I2V）—— 最高优先级

**使用方式**：这是我们的主链路。美术定调图（角色三视图 / 场景图）经人工确认后作为**首帧**输入，模型只负责让画面动起来。

**具体要求**：
- **首帧保真是硬指标**：输出视频第 1 帧必须与输入图高度一致，不允许模型对已定稿画面做重绘、改色、改构图。这一条不达标的模型对我们不可用——因为首帧是美术已经签字确认的画面。
- 支持**首帧 + 尾帧**双图输入，用于精确控制一个镜头的起止状态（例：角色从坐姿到起身）。
- 支持运镜指令：推 / 拉 / 摇 / 移 / 跟随 / 固定机位，至少覆盖这 6 种，且"固定机位"要真的不动（很多模型在无运镜指令时会自作主张地缓慢推近，导致相邻镜头拼接时观感割裂）。
- 输入图分辨率上限不低于 2048×2048，长宽比至少覆盖 16:9 / 9:16 / 1:1 / 4:3 / 3:4。

---

### 3. 一致性模型（多参考图生视频 R2V）—— 最高优先级

**使用方式**：漫剧的核心难点。同一个角色要在几十个镜头里反复出现，观众对"这还是不是同一个人"极其敏感。我们的做法是把角色三视图、场景定调图、关键道具图一起作为参考输入。

**具体要求**：
- **参考图数量 ≥ 3 张**（理想 5 张以上），且能区分参考类型：主体角色 / 场景环境 / 道具，不要把所有参考图当成同一类去平均混合。
- **跨镜头一致性**：同一组参考图在不同 prompt、不同镜头下生成，角色的五官比例、发型发色、瞳色、服装配色与款式、身高体型必须保持稳定。这是**跨调用**的一致性，不只是单条视频内部前后帧一致。
- 支持多角色同框（2–3 人对话戏），且不发生角色特征互相串味（A 的发色跑到 B 身上）。
- 参考图与 prompt 冲突时的优先级要明确、可预期：外观特征以参考图为准，动作与镜头以 prompt 为准。

---

### 4. 动漫模型

**使用方式**：我们的成片形态是短漫剧，全片必须是统一的二次元/漫画画风，不能出现某几个镜头突然"真人化"。

**具体要求**：
- 覆盖主流漫画风格：日系赛璐璐、厚涂、国漫、韩式条漫，至少提供可区分的风格档位或能通过 prompt 稳定控制。
- **不得向写实漂移**：这是动漫模型最常见的失败模式——在人物特写或复杂动作镜头下，模型悄悄把画风拉向真人质感。需要在整段视频内保持画风恒定。
- 线条与色块干净：不出现半写实的"塑料 3D 味"、脏边、色块抖动。
- 动漫场景下的手部、眼睛、发丝是重灾区，需要重点保证（详见第四节质量指标）。
- 支持动漫常见的运动表现：夸张动作、打斗、发丝与衣摆飘动、特效光效，且**打斗镜头不应被内容安全策略误判拦截**（这是我们在实际使用中遇到过的高频问题，见第五节）。

---

### 5 & 6. 4 秒 / 8 秒 时长档

**使用方式**：分镜脚本会给每个镜头预先标注时长，4s 用于快节奏对白与反应镜头，8s 用于运镜和情绪镜头。生成的片段随后要**按 BGM 节拍网格做精确裁切**再拼接。

**具体要求**：
- 两档时长都要支持，且**实际输出时长误差 ≤ ±0.1 秒**。时长不准会直接破坏节拍对齐。
- **帧率恒定**（CFR，非 VFR），24 / 25 / 30 fps 明确可选。可变帧率的片段在拼接时会产生音画漂移。
- **首尾不得自带黑帧、渐显渐入、logo 或水印**。我们需要拿到"干净的中段素材"，转场由我们自己的合成环节负责。
- 若能支持连续时长滑杆（如 2–15 秒任意取值）更好，但 4s / 8s 两档是底线要求。

## 四、效果质量要求

以下是我们判断一个视频模型"能不能进生产链路"的验收口径。建议按此提供实测数据或样片。

### 4.1 画面质量（主观 + 抽检）

| 维度 | 要求 | 判定方式 |
|------|------|----------|
| 画面稳定性 | 全程无闪烁、无背景抖动、无纹理沸腾 | 逐帧抽检 |
| 主体形变 | 角色不发生塌陷、融化、肢体增减 | 逐帧抽检 |
| 手部与面部 | 手指数量正确、面部五官不崩坏（尤其特写与快速动作） | 重点镜头人工检查 |
| 画风一致性 | 整段视频画风不漂移，不向写实滑动 | 首尾帧对比 |
| 物理合理性 | 走路不滑步、物体不穿模、重力方向正确 | 人工观感 |
| 无附加元素 | 无水印、无字幕、无 logo、无莫名文字 | 全片检查 |

### 4.2 可量化指标（希望供方提供实测值）

| 指标 | 期望值 |
|------|--------|
| **首次可用率**（一次生成即达可用标准，无需重抽） | ≥ 60%，理想 ≥ 75% |
| **跨镜头角色一致性通过率**（同参考图 10 个镜头中人工判定"是同一角色"的比例） | ≥ 85% |
| **首帧保真度**（I2V 输出首帧与输入图的视觉差异） | 肉眼不可辨 |
| **输出分辨率** | 至少 1080p；支持 720p 作为草稿快出档 |
| **码率 / 编码** | H.264 或 H.265，MP4 封装，1080p 下码率 ≥ 8 Mbps |
| **生成时延** | 8s / 1080p 单次生成 P95 ≤ 5 分钟；提供快出（草稿）档位 P95 ≤ 90 秒 |
| **任务成功率**（不含内容审核拦截的系统性失败率） | ≥ 99% |

其中 **首次可用率** 是我们最看重的一项。我们目前的成本结构里，重复抽卡是主要浪费——同一个镜头抽 4 次才有 1 条能用，意味着实际单价是标价的 4 倍。首次可用率比单次调用价格更能决定总成本。

### 4.3 "可用"的定义

一条片段被判定为可用，需同时满足：首帧忠实于输入图；全程无形变与闪烁；角色与既定设定一致；画风未漂移；时长与帧率符合要求；无水印及附加元素；动作与 prompt 描述吻合。任一项不满足即计为不可用。

## 五、接口与工程要求

我们的模型接入层是**配置化的**（每个模型家族用一份 YAML 声明其能力、参数与取值范围），因此对接口有以下要求：

1. **异步任务制**：提交任务返回 task_id，通过轮询或回调获取结果。单次 HTTP 同步等待不可接受。
2. **参数可枚举**：分辨率、时长、宽高比、参考图数量上限等，需在文档中给出明确的可选值集合，而非"支持多种规格"这类描述。我们需要据此生成前端参数面板。
3. **错误码可区分**：至少能区分"内容审核拦截 / 参数非法 / 配额超限 / 服务内部错误 / 输入图不合规"五类。目前部分供方把所有失败都返回同一个通用错误，导致我们无法做自动重试策略。
4. **并发配额**：单账号并发 ≥ 10 个任务，我们的批量抽卡依赖并发。请说明配额上限与是否可申请提升。
5. **输入方式**：参考图支持 URL 与 Base64 两种传入方式；输出结果 URL 有效期请明确（≥ 24 小时为宜）。
6. **内容审核**：短漫剧包含打斗、冲突、悬疑等剧情，需要审核策略对**虚构动漫内容**有合理容忍度。请说明审核口径，以及被拦截时是否返回可定位的原因。

## 六、产品接入形态（现状）

PrismReel 已完成模型接入框架，新模型接入无需改动业务代码，只需新增一份能力声明文件。接入点有两处：

**（1）Studio 分镜视频侧栏** —— 主生产入口

```
┌─ 分镜 #12 ───────────────────────────────────┐
│  [定调图预览]        模式: ● I2V  ○ R2V  ○ T2V │
│                      模型: [ 下拉选择        ▾] │
│  参考图: [角色][场景][道具]  (最多 5 张)        │
│  时长:   ○ 4s  ● 8s        分辨率: [1080p ▾]   │
│  运镜:   [固定机位 ▾]      画风: [日系赛璐璐▾] │
│  Prompt: [________________________________]   │
│  负向:   [________________________________]   │
│  Seed:   [______] □ 固定    抽卡数: [ 4 ]      │
│                          [ 生成 ]              │
├──────────────────────────────────────────────┤
│  产出: [片段1][片段2][片段3][片段4]  ← 择优采用 │
└──────────────────────────────────────────────┘
```

**（2）Playground 工具台** —— 独立试拍入口，同一套模型与参数，不带剧本上下文。

新模型接入所需信息：模型标识、支持的模式（t2v/i2v/r2v）、时长取值范围、分辨率选项、宽高比选项、参考图数量上限、是否支持 seed / 负向提示词 / prompt 扩写。**供方按此清单提供文档即可完成接入。**

## 七、需求优先级小结

若资源有限需要排序，我们的取舍是：

1. **一致性（跨镜头角色稳定）** —— 不达标则漫剧形态不成立，其余能力再强也无法交付成片
2. **首帧保真的 I2V** —— 决定美术定稿能否被尊重
3. **动漫画风不漂移** —— 决定成片是否像一部作品而不是素材拼盘
4. **时长精确 + 恒定帧率** —— 决定能否自动化拼接
5. **首次可用率** —— 决定实际成本
6. T2V 与更多时长档位 —— 锦上添花
